# Conditional expansion beyond the ten-identity pilot

The researcher-approved intention is a later **150–250 reviewed benign public
constructs if annotation quality, independent references and resources permit**.
This is the original four-week MVP's aspirational scale, not a current acceptance
criterion. No bulk acquisition, automatic admission or model expansion is started
by this plan. The approved ten candidates are selection decisions only; T02
source-specific review and label admission remain independent.

## Gate before expansion

Complete a small admitted pilot first. Review E1 annotation quality and justified
abstentions, E2 unit/parent coverage, a defensible E3 independent reference panel,
and actual E4 resource measurements. Resolve any parser inventions, source-rights
gaps, conflicting annotations, identity/version mismatches or leakage before
increasing the sample. If the pilot cannot support independently reviewed family
retrieval, report descriptive parsing feasibility and improve the design rather
than filling a numerical quota with weak labels.

## Staged collection and versioning

1. Freeze pilot v1 source manifests, permitted local source bytes/checksums,
   original annotations, quality strata, family definitions, reference roles and
   relatedness groups. Retain original inclusion/exclusion reasons and audit files.
2. Plan the first small increment only after researcher review of pilot evidence.
   Use bounded batches, for example 20–30 candidates, and review every source before
   admission. Stop a batch when source rights, low quality or ambiguous boundaries
   create an unresolved queue. Batch sizes are workflow guidance, not an approval.
3. Version each discovery inventory and admitted release separately. Selection
   metadata must not overwrite T02 decisions. Hash the relevant protocol/config,
   exact source versions, original files, annotations, query/reference IDs and
   labels before scoring. Corrections require a new release and stated reason.
4. Continue toward 150–250 only if successive batches add supported information
   and independent examples. A smaller defensible release is acceptable. Keep
   rejected/uncertain records and exclusion counts visible without treating them
   as negative biological examples.

## Diversity and independence targets

Use all four project archetypes where valid annotations permit: single-principal
CDS, multiple CDS, documented fusion/tag and backbone-heavy. Predeclare intended
stratum ranges after observing pilot feasibility; do not invent uniform quotas
or relabel poor records to fill a category. Include well-annotated, partial and
annotation-limited source controls only with separate T02 admission and honest
observable denominators. Noncoding/backbone information remains metadata when the
selected model has no corresponding input interface.

Select varied reporter/cloning contexts and source families, rather than many
copies of the same vector. Count parents, eligible CDSs, distinct documented
families, unique sequences and conservative relatedness groups separately. Shared
backbones, homologous reporters, repeated CDSs and exact duplicates must not
inflate independent sample size. Source taxa or vendor variety alone does not
prove sequence independence. A complete fusion is not several CDSs just because
its name lists several proteins.

Admit an independent reference collection separately. Freeze per-family support
and enough competing references to support the total K=5 budget and prespecified
difficulty tiers. Missing supported positives or competition produce abstention.
Catalogs returning every eligible reference are descriptive, not evidence of a
method advantage. Ten construct identities are not ten independent family tests;
possible pretraining overlap remains unknown.

## Rights, annotation QA and review workload

For every admitted record, a researcher records ordinary-benign rationale,
reviewer/date, exact identity/version, permitted source access/analysis/storage
and redistribution scope, retrieval date, source SHA256, original feature table,
annotation review and any source-specific restrictions. Material MTAs or public
web visibility do not establish a sequence-data redistribution license. Keep raw
sequences, original qualifier payloads, embeddings and restricted artifacts local
under ignored roots. Share only permitted metadata and properly scoped summaries.

Run the existing structural and checksum tests automatically, then manually
spot-check source CDS translation, frame/table, reverse and multipart/circular
locations, tags/fusion boundaries and noncoding labels. Review every unresolved
case rather than sampling ambiguities away. Separate source-quality failure from
parser failure; retain null denominators and justified withholding. Reaudit a
small random sample of otherwise straightforward records and double-check all
discrepancies or novel source formats. Record actual reviewer time, queue size,
exclusion rates and corrections after each batch before estimating total effort.
No unmeasured minutes-per-record or guaranteed throughput is claimed.

## Development, reference and evaluation separation

Define source-parent/relatedness groups before creating development and held-out
evaluation cohorts. Allocate linked vectors, exact copies, close reporter
variants and shared sources to the same group, and freeze independent references
with explicit overlap controls. Do not tune preprocessing rules, tier thresholds,
family labels or retrieval budgets on held-out scores. A held-out combination of
previously seen proteins is not unseen-protein generalization. Report attrition,
per-archetype coverage and group counts; use paired cluster-aware intervals only
when independent support permits them. Small or biased samples remain exploratory.

## Release and compute stop rules

Before each scored release, verify no source-rights gaps, no unapproved records,
no unsupported labels, intact T03 traceability, reproducible protocol/panel freezes,
and identical eligible reference identities across methods. Run models
sequentially until measured capacity justifies another policy. Retain loading,
first-pass inference/pooling, call/residue and cache effects separately; unavailable
memory or CPU/GPU measurements remain null. Do not automatically choose a winner.

The researcher should review the pilot findings and batch proposal before a
larger expansion. The assistant can prepare manifests, code, tests and conservative
quality guardrails; it cannot infer biological, licensing, annotation or family
approval from the delegated technical-work authority.
